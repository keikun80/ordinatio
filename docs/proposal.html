Market Challenges & Strategic Need

왜 AI Orchestrator가 반드시 필요한가?

생성형 AI 도입이 확산됨에 따라 기업과 기관은 보안 규제 위반, 통제 불가능한 인프라 비용, 무분별한 API 키 유출이라는 심각한 3대 위기에 직면해 있습니다.

데이터 유출 및 망분리 규제 위반 위협

외부 퍼블릭 SaaS LLM을 직접 호출하거나 일반 프록시를 사용할 경우, 금융/공공 고객 데이터와 사내 핵심 지적재산권이 외부로 유출될 위험이 상존합니다. 전자금융감독규정, 개인정보보호법에 따라 감사 추적 불가능한 구조는 도입 자체가 불가합니다.

해결책: 100% 온프레미스 에어갭 설치 + 자체 정규식 실시간 PII 인라인 마스킹 + WORM(Write-Once-Read-Many) 불변 감사로그 적재.
GPU 인프라 비용 폭증 및 FinOps 통제 부재

단순 질의응답이나 일상적 대화조차 고비용 최고사양 모델(Llama-3-70B, GPT-4o 등)로 무분별하게 유입됩니다. 부서별 토큰 사용량과 월간 예산 한도가 연동되지 않아 예산 초과 사고가 수시로 발생합니다.

해결책: AgentRouter 지능형 복잡도 분류(단순 질의 경량 모델 다운티어링) + 부서별 원화(₩) 예산 80% 경보 및 100% 하드캡 즉시 차단(Fail-Fast).
API Key 평문 방치 및 비인가 모델 무단 호출

개발팀마다 원천 LLM Key를 소스코드나 설정 파일에 평문으로 하드코딩하여 키 도난 및 탈취 위험이 극심합니다. 인가되지 않은 고비용 모델을 임의 호출하거나 사내 권한 통제가 전무합니다.

해결책: 원천 Key 격리 + `sk-orch-` 가상 API Key 발급 + Argon2id 단방향 솔트 해싱 + 키별 허용 모델 화이트리스트(`allowed_models`) 강제.
프롬프트 파편화 및 비즈니스 룰 탈옥 위협

서비스나 부서별로 시스템 프롬프트가 제각각 적용되어 전사적인 AI 톤앤매너, 윤리 규정, 기밀 보호 룰이 파편화됩니다. 클라이언트 단의 시스템 프롬프트 변조나 탈옥(Jailbreak) 시도를 네트워크 레벨에서 제어할 수 없습니다.

해결책: 전사/테넌트/라우트/가상키 4단계 동적 바인딩 시스템 프롬프트 카탈로그 + Envoy L7 ext_proc 인라인 강제 주입(PREPEND/OVERRIDE).

가상 API Key & 테넌트 격리 거버넌스

개발자에게 원천 모델 API 키를 일절 노출하지 않습니다. 자체 `sk-orch-` 가상 API Key를 발급하고, DB 저장 시 최고 수준의 암호화 표준인 Argon2id 솔트 단방향 해싱을 적용하여 내부 DB가 유출되어도 복호화가 불가능합니다.

  • 단 1회 평문 노출 모달: 발급 직후 1회만 화면에 노출되고 이후 절대 재확인 불가

  • 키 수명주기 2단계 보호: 긴급 파기(Revoke) 상태를 거쳐야만 영구 삭제(Purge) 허용

인라인 PII 마스킹 & WORM 불변 감사 포렌식

질의와 응답 스트림에 포함된 개인정보(주민등록번호, 계좌번호, 카드번호 등)를 1ms 이내로 실시간 탐지하고 처리합니다. 모든 통신 기록은 위·변조가 불가능한 WORM(Write-Once-Read-Many) 구조로 저장되어 금융감독원 감사에 완벽 대응합니다.

  • 3단계 보안 액션: MASK(익명화 치환), HASH(단방향 솔트), BLOCK(즉시 호출 차단)
  • WORM 불변 감사 테이블 (INSERT-only): DB 레벨 수정/삭제 불가 구조로 감사 무결성 보장
  • 다차원 포렌식 검색 & JSON 내보내기: 부서별, 키별, 일자별 정밀 감사 보고서 즉시 추출

Deployment Strategy

체계적인 3단계 도입 및 확장 로드맵

기존 애플리케이션 코드의 대대적인 변경 없이, 단 1줄의 엔드포인트 URL 변경만으로 2주 내 안전한 PoC 검증부터 전사 확대까지 단계적으로 진행할 수 있습니다.

Phase 1 · 2 Weeks

폐쇄망 인프라 구축 및 PoC 기능 검증

고객사 온프레미스 서버(Docker / K8s)에 AI Orchestrator 패키지를 100% 에어갭으로 설치합니다. 보유 중인 GPU vLLM 인스턴스를 모델 카탈로그에 등록하고, 가상 API Key 발급 및 PII 인라인 마스킹 룰을 사전 검증합니다.

Phase 2 · 4 Weeks

핵심 부서 파일럿 연동 및 AgentRouter 정책 최적화

사내 1~2개 핵심 부서(예: IT개발팀, 고객지원 챗봇)의 엔드포인트를 AI Orchestrator로 전환합니다. 부서별 원화 예산 한도(하드캡)를 적용하고, AgentRouter 4대 정책을 실시간 튜닝하여 실제 비용 절감률을 측정합니다.

Phase 3 · Ongoing

전사 확대 배포 및 WORM 감사 거버넌스 정착

전사 전 부서 테넌트로 적용 범위를 확대하고 동적 시스템 프롬프트를 일괄 적용합니다. 월간 CSV 청구서를 기반으로 FinOps 비용 정산을 정례화하며, WORM 불변 로그를 통해 상시 금융 보안 감사 체계를 완성합니다.

System Requirements

권장 온프레미스 인프라 사양

AI Orchestrator 코어 엔진은 극도로 가볍고 효율적이므로, 고가의 GPU를 요구하지 않습니다. (추론용 GPU는 기존 vLLM 노드 자원을 그대로 활용합니다)

최소 권장 사양 (PoC & 파일럿 환경)

  • CPU: 4 Core 이상 (x86_64 또는 ARM64)
  • Memory: 16 GB RAM 이상
  • Storage: 100 GB NVMe SSD 이상
  • OS: RHEL 8+, Rocky Linux 9+, Ubuntu 22.04 LTS
  • Runtime: Docker Engine 24.0+ 및 Compose v2 또는 Kubernetes 1.26+

엔터프라이즈 HA 사양 (전사 고가용 프로덕션)

  • CPU: 8 Core 이상 x 2 노드 (Active-Active)
  • Memory: 32 GB RAM 이상 x 2 노드
  • Storage: 500 GB 고속 NVMe (WORM 감사로그 보관용)
  • DB: 사내 고가용 PostgreSQL 15+ 클러스터 연동 지원
  • Cache: 사내 Redis Cluster 연동 지원 (분산 Rate Limiting)
